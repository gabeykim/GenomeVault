# Proposal: adaptive questions: typo-tolerant names with confirmation, and private cloud lookup beyond the pack

- **From:** human (Dhiaa, B owner) · **Time:** 2026-11-08 16:55 · **Against:** PLAN v1.3.4
- **Type:** invariant change (needs human): touches I4 (name normalization path) and I5 (adds a second fixed partition). Human approval given by Dhiaa; integrator ruling needed from Gabe.
- **Problem:** Typed questions are brittle. (1) A typo ("clopidogrl") matches no exact key and returns `no_data`. (2) A pair outside the 136-key partition is never looked up in the cloud, so it can only be `no_data` (and today it can wrongly read as "checked"; see to-B 20261108-1645). Judges will type their own questions; the demo should handle them.
- **Proposed change** (every part behind a flag; default ON only if green by 18:00, otherwise shipped OFF so the demo is unchanged):
  1. **A · `normalize.suggest(text)` (flag `GV_FUZZY=1`).** Stdlib only (difflib / edit distance, no new dependency). For each unmatched token, rank candidates from the name lexicon. Exactly one candidate within distance ≤ 2 and the runner-up ≥ 2 further: return it as **assumed**. Otherwise return up to 3 **choices**. A small authored list of look-alike/sound-alike names (e.g. clonidine / clopidogrel / clozapine, hydroxyzine / hydralazine) is always **ask**, never assume. A corrected name re-enters the normal exact-key path (I4 holds: no fact is ever looked up under a guessed key without being shown to the user).
  2. **B · long-tail partition (flag `GV_TAIL=1`).** `data/buckets/tail-v1.json`: a fixed, versioned partition (k = 8) of every drug–drug pair over A's ingredient vocabulary, plus drug–lab bands, assigned deterministically once (seeded; grouped by frequency tier where priors exist) and committed. Same file for every user; never built from a query (I5 holds). Router order: core partition → KB → core bucket (unchanged); key in tail partition and not in KB → send its tail bucket through every P6 step (generalize, split, delays, cover, leakage check, ledger) and store all 8 answers; key in neither (unknown term) → `no_data` plus an optional consent path (part 4).
  3. **B · demo fallback (flag `GV_DEMO_LIVE_FALLBACK=1`).** With `DEMO=1`, a cache miss falls back to a live call when online, so the stage replays the pack but can still look up a new pair live. Forced offline wins, as now.
  4. **C · UI.** "I'm assuming you mean X" banner with a one-tap "Not what I meant"; "Did you mean: X / Y?" chips that hold the answer until chosen; a consent dialog for an unknown term ("This question can't be hidden in a group. Send it on its own?"), logged in the ledger as `single, not hidden`; ledger label `tail` for long-tail buckets.
  5. **D · eval.** Add the tail partition to E1 and report its repeat-ask and statistical-attacker numbers separately (expected weaker than the frequency-balanced core: say so on the slide). Add a 20-item typo set, including look-alike names: report correct suggestions and **zero silent wrong substitutions**.
- **Affects:** A (normalize), B (decoys, router, cloud), C (ask UI, ledger), D (E1, new typo test), I (PLAN P6, I4/I5 wording, gates).
- **Migration:** additive. Existing keys, the core partition v5 and the knowledge pack are unchanged; all new behavior is off unless its flag is set.
- **If rejected:** keep the scripted chips on stage, ship B's uncovered-pair `no_data` fix, and present typo tolerance and long-tail lookup as roadmap.

**Timebox:** each part lands behind its flag by 18:00 with tests green, or ships off. Nothing here may delay G4 (18:15) or the freeze (18:30).
