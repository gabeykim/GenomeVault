# GenomeVault

**A private health agent that keeps your genome on your device.**

GenomeVault checks any new medication against your genes, records and bloodwork, entirely on your own machine. When it needs deeper medical reasoning, it asks the cloud only generalized, decoy-protected questions, so the cloud never learns who you are or what you have. Every cloud answer is stored locally, so the agent needs the cloud less the more you use it.

> **Demo, not medical advice.** All patient data in this repo is synthetic. GenomeVault prepares you for a conversation with your pharmacist or doctor; it never tells you to start or stop a medication.

Built at the **Lenovo × AGI House hybrid AI build day** (November 2026).

## Why

Whether a drug is right for you depends on three things:

- **Your genes.** Some people can't activate certain drugs, or clear them as fast.
- **Your body right now.** Kidney and liver function, potassium, and other lab values.
- **Your other medications.** Drugs that interfere with each other.

That information is scattered, and it is some of the most private data you have. Sending all of it to a cloud AI is a privacy and compliance problem. GenomeVault keeps the data where it is and moves only safe, general questions.

## How it works

Meet **Alex** (synthetic): 58, just discharged after a coronary stent, with five new prescriptions.

1. **Capture.** Alex photographs his prescription labels on his phone. The laptop reads them and converts each to its active ingredient.
2. **Check locally.** A rules engine compares each drug with Alex's genotypes, labs, allergies and other meds using fixed lookup tables, not an AI guessing. It flags four problems instantly, with nothing sent anywhere.
3. **Ask the cloud privately.** For an open question ("What should I bring up with my cardiologist?"), the privacy router turns Alex's situation into general questions, splits them up, and hides each one in a fixed group of 8 realistic questions.
4. **Personalize locally.** General answers come back; the laptop combines them with Alex's private results into an answer about him.
5. **Act.** It drafts a message to his pharmacist, a one-page visit summary, and a reminder on his phone.
6. **Learn.** All cloud answers, decoys included, are stored on the laptop. Related questions are answered locally next time.
7. **Work offline.** With no connection, the rules engine and stored knowledge keep working.

### The privacy stack

Each step runs only if the previous one could not answer:

| Step | What happens | Sent to cloud |
| --- | --- | --- |
| 1. Local rules | Deterministic gene, drug, lab and allergy checks | Nothing |
| 2. Knowledge base | Exact-key lookup of previously fetched answers | Nothing |
| 3. Generalize | Ask about all phenotypes and lab ranges, never yours | General question |
| 4. Split | One concept per request, separate sessions, random delays | No combined picture |
| 5. Bucket | The real question travels inside a fixed group of 8 | Attacker guesses 1 in 8 at best |
| 6. Cover traffic | Decoy buckets on a steady schedule | Hides when you're active |
| 7. Leakage check | Blocks any outbound text containing personal fields | Zero personal fields |
| 8. Ledger | Logs everything that left, shown live in the UI | Auditable |

### Safety rules

- **No guessing between drugs.** Every fact is keyed to exact ingredients. Knowing omeprazole + clopidogrel says nothing about pantoprazole + clopidogrel (they actually differ). A missing key means "no data, ask your pharmacist."
- **Trust tiers.** Serious warnings require facts from curated guidelines. Cloud-generated facts are labeled "AI-summarized, verify" and expire sooner.
- **Never "safe."** At most: "no interaction listed in [source]."

The full list of invariants is in [`coord/PLAN.md`](coord/PLAN.md) (P4).

## Proof

We measure the privacy and hybrid claims instead of asserting them. Results are generated by `make eval` and written to [`docs/results.md`](docs/results.md).

| Test | Question | Target |
| --- | --- | --- |
| Red team | Can an attacker who sees all outbound traffic recover Alex's genes, meds or conditions? | Naive: yes. Random decoys: partly. GenomeVault: about 1 in 8 |
| Joint inference | Can simultaneous questions be combined to reveal a condition? | No better than chance |
| Learning curve | Does cloud usage fall over 20 questions? | Steep drop after warm-up |
| Latency and cost | Hybrid vs local-only vs cloud-only | Cloud-level quality at a fraction of cloud calls |
| Offline | How much still works with Wi-Fi off? | Cold vs warm knowledge base |

## Quick start

Requirements: Python 3.10+, a local model server (Ollama or llama.cpp) for the on-device model, and an API key for the cloud model.

```bash
git clone https://github.com/<owner>/genomevault.git
cd genomevault
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # fill in ANTHROPIC_API_KEY, CLOUD_MODEL, LOCAL_LLM_MODEL

make test                   # all tests
make demo                   # demo mode: replays cached cloud answers, works offline
make eval                   # regenerates every proof chart into docs/
```

## How this repo is built

GenomeVault is built by **four autonomous coding agents** working in parallel, each watched by a human, plus a human integrator.

| Agent | Branch | Builds |
| --- | --- | --- |
| A · data-rules | `agent/A-data-rules` | Synthetic data, normalization, rule tables, rules engine |
| B · privacy-router | `agent/B-privacy-router` | Generalizer, decoy buckets, knowledge base, cloud client, ledger, validator |
| C · app-ui-actions | `agent/C-app-ui` | UI, phone page, merge, actions, demo mode |
| D · eval-redteam | `agent/D-eval` | Evaluations, attackers, charts, slides, docs |
| Integrator (human) | `main` | Plan, decisions, contracts, merges at gates |

**How they stay in sync.** The agents coordinate only through files in this repo, and no two agents ever write the same file:

- [`coord/PLAN.md`](coord/PLAN.md) is the source of truth, with stable IDs (F features, M modules, I invariants, S demo beats, G gates) and a version number.
- [`coord/DECISIONS.md`](coord/DECISIONS.md) logs every accepted change.
- Each agent keeps a brief, a live status, and an append-only log of impact reports in `coord/agents/<ID>/`.
- Agents message each other with new files in `coord/inbox/` and request plan changes with new files in `coord/proposals/`.

**Every change is classified.** *Advances* builds what the plan says. *Refines* decides a detail the plan left open. *Alters* changes the plan, a contract or an invariant, and needs the integrator's approval first. Every code commit carries trailers naming its class, the plan IDs it touches, and the agents it affects; every commit gets an impact report. The full protocol is in [`AGENTS.md`](AGENTS.md).

**Guardrails.** CI rejects commits that touch files the agent doesn't own, code commits without impact trailers, and network code outside `core/cloud.py`. Agents escalate to a human when an invariant would change, tests stay red, or a task fails three times.

### Running the agents

```bash
# integrator, once: create agent branches + code and coordination worktrees
bash scripts/setup_worktrees.sh

# each human, one terminal per agent
cd ../gv-A && AGENT=A VENV="$PWD/../genomevault/.venv" ./scripts/agent_loop.sh
```

Pause one agent by committing `coord/agents/<ID>/STOP` to `main`; stop all by committing `coord/FREEZE`.

## Limitations

- Consumer genotype arrays miss some variants (for example CYP2D6 copy-number changes); real use needs clinical-grade data.
- Rule tables cover a demo subset of drugs, genes and labs, not all of them.
- Decoy privacy is probabilistic: the best case is 1 in k, not zero.
- Network metadata (IP address, account, timing) is not hidden yet; a relay layer is on the roadmap.
- Encryption at rest protects a locked device, not a stolen unlocked one.

## Roadmap

- Replace the hand-coded genotype lookup with PharmCAT; real FHIR import.
- Relay layer for network metadata; bulk knowledge-pack sync so refreshes reveal nothing.
- Clinic mode on an edge server for pharmacies and practices.
- Federated cohort queries across sites without moving genomes.
